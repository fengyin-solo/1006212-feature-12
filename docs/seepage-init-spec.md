# 渗流测点示例数据与初始化口径

口径版本：`2026.10.05-seepage-v1`（写在 `frontend/src/data/seepage/policy.json`，并随
`generated-seed.json` 进入 localStorage 版本校验）。本文件是对该口径的说明，冲突时以
`policy.json` 与 `seepage-core.js` 实现为准。

## 1. 数据窗口与粒度

- 窗口：2026-01-01 ～ 2026-01-31；
- 每个测点每日两个时段：上午、下午，一个时段即「半天」；
- 3 个基础测点 × 31 天 × 2 时段 = **186 条**初始化记录；
- 记录按 测点编号 → 监测日期 → 监测时段 稳定排序，id 随排序重新编号，因此反复生成、
  反复初始化结果完全一致。

## 2. 基础数据与示例数据（单独另存核对）

| 角色 | 文件 |
| --- | --- |
| 口径（窗口/分档/阈值/去重/回填/权威结论） | `frontend/src/data/seepage/policy.json` |
| 基础点位数据（点位台账参数，不含读数） | `frontend/src/data/seepage/points.base.json` |
| 示例观测（缺测时段、重复提交、无日期存量） | `frontend/src/data/seepage/observations.sample.json` |
| 共享核心逻辑（生成与浏览器同一份） | `frontend/src/data/seepage/seepage-core.js` |
| 初始化产物（前端唯一读取） | `frontend/src/data/generated-seed.json` |
| 另存核对（CSV + 说明） | `data/export/` |

`observations.sample.json` 只描述相对完整序列的偏差（缺测、重复、存量）；其余时段读数由
点位参数经确定性公式合成，完整逐时段原始快照另存为
`data/export/seepage-observations.raw.csv`，可脱离页面单独核对。

另存文件：

- `seepage-points.base.csv`：基础点位（3 行）；
- `seepage-observations.raw.csv`：原始观测快照（187 行，含 1 行被拒收的重复提交，缺测留空）；
- `seepage-records.processed.csv`：处理后权威台账（**186 行，与页面记录数一致**）；
- `seepage-duplicates.rejected.csv`：被拒收的后到重复提交（1 行，只留痕）。

## 3. 缺测时段分档处理

「连续中断」按同一测点相邻半天时段计算，指标以测压管水位为空判定（渗流量、扬压力同时缺）：

| 分档 | 连续中断时段数 | 处理 |
| --- | --- | --- |
| 半天 | 1 个时段 | 取相邻前后时段读数线性内插补齐 |
| 一天（1 天以上、3 天以内，含 2 天） | 2～5 个时段 | 取缺口前后有效读数线性内插补齐 |
| 三天以上 | ≥6 个时段（连续 3 天及以上） | **不补数值**，按缺测保留 |

- 线性内插仅在缺口前后都有有效读数时生效（窗口边界缺测按三天以上处理保留缺测）；
- 所有由缺测补齐的记录保留 `原始缺测=是`，并在 `缺测处理` 写明分档方法，
  `数据来源` 标注「示例观测·内插」，不抹掉缺测痕迹；
- 三天以上缺测记录三项数值留空，页面显示「缺测」，`测点状态=缺测（三天以上）`，
  且不计入渗流量、扬压力合计。

本期示例：SEEP-0001 在 1 月 10 日上午缺 1 个时段（半天内插）；
SEEP-0003 在 1 月 20 日缺 2 个时段（一天内插）；
SEEP-0002 在 1 月 15 ～ 19 日连续缺 10 个时段（保留缺测，不补）。

## 4. 预警判定阈值（本地与部署同一套）

任一指标达到报警线即「报警」，否则任一达到预警线即「预警」，全部低于预警线为「正常」。

| 指标 | 预警线 | 报警线 | 单位 |
| --- | --- | --- | --- |
| 测压管水位 | 245.0 | 248.0 | m |
| 渗流量 | 2.5 | 3.2 | L/s |
| 扬压力 | 180 | 200 | kPa |

阈值只存在于 `policy.json`，页面「警戒数值」列与阈值说明均由此渲染；
`seepage-core.js` 据此算 `status/pending/abnormal`，不存在本地一套、部署一套。

## 5. 重复登记与权威结论

- 登记键：`测点编号 + 监测日期 + 监测时段`；
- **只认第一次取值**：同一键后到的提交按重复处理，不进入台账，原值写入
  `seepage-duplicates.rejected.csv` 留痕（示例：SEEP-0001 在 1 月 12 日下午的第二次提交，
  999.9 等异常值被拒收）；
- 权威结论：去重、存量回填、缺测补齐后的 `processed` 结果是**唯一**初始化数据；
  原始观测、拒收重复、三天以上缺测只在 `data/export` 留痕；
- 生成写盘走「临时文件 + rename」，localStorage 读取后在内存整体替换再一次性写入，
  重复提交只生效一次，覆盖的那一版不留中间态。

## 6. 存量记录回填（早期缺监测日期）

- 同一测点的记录按监测日期升序；
- 早期纸质台账转录、**缺监测日期**的记录：先按测点编号、再按原始登记顺序，
  回填到该测点序列中最早可用（非缺测）的半天时段，每条约占一个时段；
- 回填记录数值沿用原始台账、不做插值，`数据来源=存量台账回填`，
  `测点状态` 注明「存量回填（早期无监测日期，按登记顺序）」。
  这是「按什么顺序补」的既定决定：监测日期优先，无日期的用测点编号 + 登记顺序兜底，避免日期冲突。

## 7. 总量与环境一致性

- 渗流量合计（三天以上缺测不参与求和）、扬压力合计、有效读数条数、记录数、状态分布、
  记录数组的 SHA-256 校验和都写入 `generated-seed.json.seepage` 与另存 README；
- `npm run seed:check` 用当前口径在内存重算并与已提交产物逐行比对；
  `predev` 与 `prebuild` 都执行，Docker 多阶段构建同样执行——
  本地开发与部署环境读同一份初始化结果，换环境后渗流量与扬压力总数必须对得上；
- 渗流页面页脚实时重算合计并与初始化口径值对照，一致时显示「一致」。

## 8. 反复初始化幂等

- localStorage 增加口径版本号（`hydropower-plant-om:seed-version`）：
  版本不符（首次打开、口径升级、旧的随手填脏数据）时整版替换为当前口径结果；
- 每次读取与 `resetModule('seepage')` 都跑同一套去重 + 稳定排序规范化，
  即使输入含重复键，输出行数与登记键集合也不变，不会多出重复测点。

## 9. 导轴承（牵动待办清单）

导轴承示例数据同由 `build-seepage.mjs` 确定性生成（4 台：2 正常、1 温度偏高、1 待检修，
其中待办 2 台）。导轴承页统计卡片与运营概览入口都读同一份 `generated-seed.json`，
待办台数跟着渗流这一步的重建统一变化。存量台账按检测日期（记录时间）回填；
早年纸质台账缺检测日期的项目作为缺项另行登记，不在示例数据内补造。

## 10. 复现命令

```bash
cd frontend
npm install
npm run seed:build   # 重新生成 generated-seed.json 与 data/export
npm run seed:check   # 校验产物 == 口径重算
npm run build        # 校验 + 类型检查 + 生产构建（一条流水线）
```
